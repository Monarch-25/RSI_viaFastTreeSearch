## 0. Ground rules (read before anything else)

### 0.1 Division of labor — who does what (frozen for the whole build)

| Actor | Does | Never does |
|---|---|---|
| **Strict modules** (deterministic code; Bedrock LLMs only where stated) | ingestion, normalization, offset indexing, scoring, judging (Sonnet 4.6), BT fitting, sampling, queueing, sandboxing, reporting, ledger | propose product code changes |
| **VS Code Copilot coding agent** | **ONLY this:** given a sampled parent + module-provided context, author ONE new candidate evolution (code/prompt/config patch) and its self-check | run evals, touch the benchmark, judge candidates, modify harness/scorer/vault, promote anything |
| **Human (PM / Dev / Owner)** | PM triage (defect vs preference), Dev feasibility, evolve-approval per run, promote-approval | — |

If a task is not "author a candidate patch from a sampled parent," it belongs in a strict module.

### 0.2 Model wiring (frozen)

| Role | Model | Notes |
|---|---|---|
| Injector (dataset) | Bedrock family-A frontier (set `INJECTOR_MODEL`) | Low temperature, diff-contract prompts |
| Verifier (dataset) | Bedrock family-B (**must differ from injector family**) | 3 independent rounds, temperature 0 |
| Judge (evolution) | **Bedrock Sonnet 4.6** (`JUDGE_MODEL`) | Pairwise, full candidate files + samples |
| Coding agent | VS Code Copilot (Claude models) | Candidate authorship only |

> ⚠️ **Same-family warning (from your answers).** You plan Haiku as the second Bedrock model. Haiku is
> Anthropic — the **same family** as Sonnet — so injector↔verifier would be *intra-family*, which the
> 37-model verification literature shows inflates false positives (verifiers accept outputs that resemble
> their own distribution). Two options, pick one in Phase 0 and record it in `model_plan.md`:
> **(a)** use a non-Anthropic Bedrock family (Llama / Mistral / Nova) as verifier; **(b)** keep Haiku but
> compensate with oracle-first verification + **3× human audit rate** and stamp affected labels
> `silver*` with the caveat in `bench_report.md`. Default recommendation: (a).

## PHASE 1 — Dataset creation (the benchmark everything hill-climbs)

**Goal:** frozen `BENCH_DIR/bench_v7/` the evolution can score against but never modify.
**Agent skill to follow:** `skills/proofreader-dataset-builder/SKILL.md` — execute its §3 pipeline in order.
**Copilot role in this phase:** NONE for labels. Copilot may author pipeline *tooling* (renderer, oracles,
validators) but never label content; labels come from injector→verifier→human-audit loop only.

### 1.1 Freeze taxonomy + write oracles
Parse `TAXONOMY_MD` → `taxonomy.json` (`rule_id, family, definition, severity, deterministic, oracle,
exemplars`). Write deterministic oracles as code first (datetime regex, trademark gazetteer + first-mention
detector, units, capitalization), each with ≥20 unit tests incl. adversarial cases (datetimes in code quotes,
marks in URLs). Ambiguities → `adjudication_log.md`, one recorded decision each.

### 1.2 Coverage sampling (small-pilot quotas)
Matrix `rule × domain × density{single,multi} × {target, distractor, minimal_pair}`; quotas: **≥8 discovery +
≥4 holdout items per rule** (~60 discovery + ~30 holdout docs total). Splits **by document**. Reserve 2–5% of
holdout as canaries (unique nonsense marks, sealed file, restricted read).

### 1.3 Inject → verify → render → distractors → pairs
Per SKILL.md Stages 4–7: diff-contract injection (one error/item, injector family-A) → oracle pass → 3-round
cross-family verification (accept iff all rounds ≥4/5; 20–40% rejection budget; <10% rejection = verifier too
lenient, tighten it) → PDF render with text layer → pymupdf anchor resolution (unresolvable = reject) →
≥30% minimal-pair mates + ≥25% near-miss distractors (verified clean by oracle + verifier).

### 1.4 Freeze bench_v7 + human audit
Stratified human audit: 10–15% sample + 100% of canaries/adjudications. Run `scripts/validate_item.py`
on 100% of rows. Write `bench_report.md` (counts, agreement, κ, anchor rate, rejection rate, diversity).

### ✅ VERIFICATION GATE 1 (all must pass before Phase 2)
- [ ] `taxonomy.json` covers 100% of `TAXONOMY_MD` rules; every deterministic rule has a tested oracle.
- [ ] Coverage matrix ≥95% filled at quota; zero doc/passage/near-dup overlap discovery↔holdout.
- [ ] Human spot-audit **κ ≥ 0.75** on spans+rules; canary file sealed.
- [ ] PDF anchor resolvability **≥99%**; `validate_item.py` clean on 100% rows.
- [ ] `bench_report.md` + frozen tag `bench_v7` (SHA-256 of `items.jsonl`) recorded.
- [ ] No baseline-pipeline artifact anywhere in provenance (independence check).

## PHASE 2 — Initial harness (lake, adapter, scorer, vault)

**Goal:** runnable local harness where a candidate can be scored deterministically.
**Copilot role:** may scaffold module code from the specs below; harness modules are strict (deterministic),
except the judge caller (Sonnet 4.6) in Phase 4.

### 2.1 Context lake connectors (`lake/`)
Six connectors, each `pull --source <name> --run-id <id>`, idempotent, landing normalized data +
`lake_manifest.json` (URIs + SHA-256 + counts): `codebase` (git SHA + image digest), `langsmith`
(run/doc/time/chain/prompt-hash/chunks/model/tokens/latency), `bedrock-logs`, `documents` (UTF-8 + offset
index `page → (char_start, char_end)`), `feedback-csv` (schema-validated, NFKC), `style-guide` (pinned ver).

### 2.2 App adapter + sandbox (`harness/adapter/`)
Sole contract evolution touches: `run(doc_bytes) -> spans[]` (`span = {char_start, char_end, rule_id,
confidence, suggestion, highlight}`). Candidate = versioned local build (image or venv hash). Sandbox: no
network except Bedrock proxy, 2-min/doc timeout, memory cap. Strict module; Copilot never edits it.

### 2.3 Deterministic scorer + verifier (`harness/scorer/`, frozen before any search)
Span TP iff `IoU ≥ 0.5` + rule-alias match. Per-rule $P_r, R_r, F_{1,r}, H_r, A_r$ (§5 of research draft),
composite $S(c)$, guardrail `Regress(c)`, canary check. Only interface: `score(candidate_id, suite)` →
`{suite_score, per_rule, per_doc, cost_usd, latency_p95, verdict, eval_id}`; `finalize` is human-gated, once
per run, and is the only path to holdout.

### 2.4 Benchmark vault, local (`bench/vault_api/`)
Serves `BENCH_DIR` read-only: discovery/proxy suites via `/score`; holdout only via gated `/finalize`.
Pins `bench_ver` (docs + labels + scorer + judge-rubric hashes). Separate OS user / read-only mount so the
coding agent *cannot* write even by accident. Memoize `(code_hash, doc_id, scorer_ver) → score`.

### ✅ VERIFICATION GATE 2
- [ ] Each connector re-runnable with identical checksums; ≥99% feedback rows resolve to offsets
      (rest quarantined with reasons); ≥90% rows join to a LangSmith run.
- [ ] Adapter runs prod baseline end-to-end in sandbox; scorer reproduces hand-computed $S(c)$ on 5
      fixture docs exactly.
- [ ] Vault serves proxy + discovery; holdout unreachable except via `finalize`; write-attempt from a
      dummy candidate fails (negative test).
- [ ] Fixture: 5 smoke docs with known scores green.

## PHASE 3 — Diagnose, gates, search context (M1 → human → M2)

### 3.1 Module 1 — Diagnose (`modules/m1_diagnose/`, triggered by script)
Ingest lake → normalize → offset-resolve (split `highlighted=false` into pred-span + attempted anchor) →
trace-join (`retriever_miss_rate`, prompt-hash frequency) → exact→MinHash→embedding dedup → cluster into
`FN_detection / FP_overflag / HIGHLIGHT_grounding / SUGGESTION_quality` → severity
$s=\sigma(w_1R_{\mathrm{miss}}+w_2\mathrm{FP}+w_3H_{\mathrm{fail}}+w_4\mathrm{cov}+w_5b_{\mathrm{rule}})$ →
`pm_issue_list.{csv,json}` + `manifest.json`. PM triage UI (or CSV round-trip): per issue
`APPROVE_DEFECT / PREFERENCE_IGNORE / NEED_EVIDENCE` + rationale; ignored items become
do-not-optimize constraints.

### 3.2 Module 2 — Search context (`modules/m2_searchctx/`)
Dev marks feasible subset → module emits `search_context.json`: approved issues, pathways
(PATH-A highlight / PATH-B retrieval / PATH-C prompt-decompose / PATH-D routing-threshold), MCP connectors
(code search, trace search, proxy `/score`, doc store), **diverse initial seeds incl. weak-but-distinct**
(regex trademark, rule-based datetime — LEVI lesson), constraints, budgets. Every evolution run requires
owner approval of pathways + caps before starting.

### ✅ VERIFICATION GATE 3
- [ ] M1 reproduces a hand-built 20-row fixture exactly (dedup groups, severity order, pathway hints).
- [ ] PM round-trip works: edited CSV re-validates without re-ingest; ignored issues appear as constraints.
- [ ] `search_context.json` validates against schema; all seeds build/run; connectors answer sample queries.

## PHASE 4 — Evolutionary search (SIFT-style; Copilot authors candidates here)

### 4.1 Who does what in the loop (enforced, not advisory)
- **Strict modules:** parent sampling, candidate build/test harness, smoke runner, judge caller (Sonnet 4.6),
  BT refit, priority queue, async orchestration, ledger, guardrail scanners.
- **Copilot (only job):** input = sampled parent snapshot + failure context + constraints; output = ONE
  candidate patch (code/prompt/config diff) + its self-check result. It sees proxy scores only, never holdout,
  never the scorer internals, never the vault.

### 4.2 The loop (three fidelities, async)
1. **Sample parent** (strict): $P(i)\propto\exp(-\alpha r_{\mathrm{BT}}-\beta r_{\mathrm{acc}}-\eta\log(1+v_i))$;
   unevaluated nodes inherit parent accuracy. 90% refine / 10% paradigm-shift routing per LEVI.
2. **Expand via Copilot:** module sends parent files + failing traces + verifier messages (GEPA reflection) +
   constraints; Copilot returns patch. Novelty filter (embedding cosine >0.95 → LLM novelty vote) drops dups
   before any paid eval.
3. **Smoke** (strict, free gate): 4 fixed docs; failures rejected without judging.
4. **Judge** (strict caller, Sonnet 4.6): pairwise vs ≤10 incumbents from archive top by (BT rank, accuracy
   rank); **full candidate files + 3–5 sample outputs** as input (SIFT: full-files ρ≈0.68 vs diffs ≈0.40);
   judge prompt includes *"prefer changes live on the execution path; penalize disabled verifiers, dead
   flags, relaxed budgets."* Win/loss → refit regularized BT ($P(i\succ j)=\theta_i/(\theta_i+\theta_j)$).
5. **Async priority eval** (strict): queue ordered by same rank mixture; proxy (80% of evals) → full
   discovery for finalists → holdout once via gated `finalize`. Expansion never blocks on eval
   (disaggregated workers).
6. **Guardrails** (strict, every candidate): diff-scanner rejects vault/bench/scorer edits; suppression
   detector flags recall-drop/precision-rise patterns; canary + sandbox-egress checks.
7. **Stop:** budget ($25) ∨ 250 evals ∨ 12h ∨ $\Delta S_{\mathrm{best}}<\varepsilon$ for 30 evals ∨ human stop.
   Promotion = full + holdout + diffs + judge rationale → human approve/rollback.

### ✅ VERIFICATION GATE 4 (dress rehearsal before real budget)
- [ ] Dry run with $2 cap completes: sample→Copilot patch→smoke→judge→BT refit→1 proxy eval→ledger entry.
- [ ] BT strengths move sensibly on a rigged A/B (known-good vs known-broken parent).
- [ ] Guardrail negative tests pass (vault-edit patch rejected; suppression pattern flagged).
- [ ] Cost ledger matches Bedrock invoices within 5%.

**Surfaces (strict modules):** pathways view (approve A/B/C), discovery tree (node → diff + traces + scores),
hillclimb chart (best-so-far + cost burn-down + per-rule subplots; template `figs/fig1_hillclimb.png`),
run ledger ($/tokens/latency per candidate×doc). System diagram source of truth:
`auto-evolution-hld.excalidraw` (regen `gen_excalidraw.py`; Obsidian copy in vault `Excalidraw/`).

### ✅ VERIFICATION GATE 5 (per evolution run)
- [ ] Promotion packet complete: trajectory, per-rule deltas, cost, holdout score + gap, guardrail report.
- [ ] Human decision + rationale archived; rejections feed back as constraints to the archive.

### Iteration protocol (how we work with this doc)
1. Say which phase + gate you are at; paste failing checks verbatim.
2. One phase at a time; no skipping gates. Schema/contract changes require bumping the version string in
   the affected file + a line in this doc's changelog (§6).
3. Copilot tasks must cite the exact module + input snapshot (`parent_id`, `search_context` hash).
